# 2026-08-08

## 오늘 공부한 것

- 파일 처리

## 핵심 개념

**파일 저장의 필요성**
- 프로그램의 실행/종료 여부와 무관하게 데이터를 보존하고 싶다면, 데이터를 파일로부터 입력받고 결과를 파일로 저장해야 함

**텍스트 파일 vs 이진 파일**
- 텍스트 파일: 사람이 인식할 수 있는 문자를 담은 파일, 메모장 등 별도 프로그램 없이 읽을 수 있음. 모든 데이터가 문자 형식으로 변환되어 기록됨(예: 정수 10 → 문자 '1', '0'으로 저장). 이진 파일보다 공간을 많이 차지하고 입출력 속도가 느림
- 이진 파일: 컴퓨터가 인식할 수 있는 데이터를 가진 파일, 특정 응용 프로그램을 이용해야 액세스 가능(예: ppt). 메모장으로 열면 알아볼 수 없는 문자들로 표시됨. 데이터가 문자로 변환되지 않고 그대로 저장됨(예: 정수 10 → 10을 나타내는 이진 비트값 그대로 저장). 텍스트 파일보다 저장 공간을 적게 차지하고 입출력 속도가 빠름
- 파일을 사용하려면 반드시 열고 닫는 과정이 필요함

**파일 위치**
- 파일의 위치는 현재 작업 폴더(작업이 이루어지는 폴더, 보통 실행 파일이 위치한 폴더) 기준으로 결정됨
- CMD(명령 프롬프트): 텍스트 기반 사용자 인터페이스, 탐색기와 비슷한 역할. `cd`(폴더 이동), `dir`(폴더의 파일 목록 표시)가 기본 명령어

**FILE 포인터와 표준 스트림**
- `FILE *fp;` → `FILE`은 파일 입출력에 필요한 정보를 담은 구조체, 파일마다 하나의 FILE 포인터를 연결해서 사용
- 표준 스트림은 별도로 열거나 닫을 필요 없음
  - `stdin`: 표준 입력 스트림, 키보드로부터 입력받음
  - `stdout`: 표준 출력 스트림, 모니터로 결과 출력
  - `stderr`: 표준 오류 출력 스트림, 모니터로 오류 메시지 출력

**파일 열기 — `fopen()`**
- 함수 원형: `FILE *fopen(char *filename, char *filemode);`
- 인자: `filename`(연결할 파일 이름, 상대경로 또는 절대경로), `filemode`(파일 접근 방식)
- 절대경로: 드라이브명부터 파일 위치까지 전체 경로 / 상대경로: 현재 작업 폴더 기준 경로
- 반환값: 성공 시 FILE 포인터, 실패 시 NULL → **반환값은 반드시 검사해서 파일이 정상적으로 열렸는지 확인해야 함**

파일 접근 모드:

| 텍스트 모드 | 이진 모드 | 기능 |
|---|---|---|
| `r` | `rb` | 읽기 전용. 파일을 열 수 없으면 NULL 반환 |
| `w` | `wb` | 쓰기 전용. 파일 없으면 새로 생성, 있으면 기존 내용 삭제 후 새로 생성 |
| `a` | `ab` | 추가 전용. 파일 없으면 새로 생성, 있으면 기존 파일 끝에 내용 추가 |

- 모드에 `+`를 붙이면 읽기/쓰기 모두 가능

예시:
```c
FILE *fp  = fopen("test.txt", "r");
FILE *fp2 = fopen("C:\\MY\\DATA\\test.txt", "a");
FILE *fp3 = fopen("..\\DATA\\test.txt", "w");
FILE *fp4 = fopen("DATA\\test.txt", "r");
```

**파일 입출력 함수 정리**

| 처리 대상 | 처리 단위 | 입력 | 출력 |
|---|---|---|---|
| 텍스트 파일 | 문자 | `fgetc()` | `fputc()` |
| 텍스트 파일 | 문자열 | `fgets()` | `fputs()` |
| 텍스트 파일 | 지정 형식 | `fscanf()` | `fprintf()` |
| 이진 파일 | 블록 | `fread()` | `fwrite()` |

- `fscanf(FILE *fp, char *format, ...);` — 지정한 형식으로 데이터를 읽음, 여러 형태의 자료를 한 번에 입력 가능. 성공 시 입력한 변수 개수 반환, 실패 시 EOF 반환
- `fprintf(FILE *fp, char *format, ...);` — 지정한 형식으로 파일에 출력. 성공 시 출력한 바이트 수 반환, 실패 시 음수 반환
- `fgetc(FILE *fp);` — 문자 하나 읽음. 성공 시 읽은 문자, 실패 시 EOF 반환
- `fputc(int ch, FILE *fp);` — 문자 하나 출력. 성공 시 출력한 문자 ch 반환, 실패 시 EOF 반환
- `fgets(char *s, int n, FILE *fp);` — 문자열을 읽어 `s`에 저장(`n`은 널 문자 포함 최대 저장 개수). 성공 시 `s` 반환, 파일 끝 도달이나 오류 시 NULL 반환
- `fputs(char *str, FILE *fp);` — 문자열을 파일에 출력. 성공 시 출력한 바이트 수 반환, 실패 시 EOF 반환

**파일의 끝 확인 — `feof()`**
- 함수 원형: `int feof(FILE *fp);`
- 파일 끝까지 데이터를 모두 읽은 상태인지 확인. 파일 끝이면 0이 아닌 값, 아니면 0을 반환`
- **주의**: EOF 문자를 "만나는 순간" 바로 0이 아닌 값이 되는 게 아니라, EOF를 읽으려고 **시도한 이후에** 0이 아닌 값으로 바뀜(한 박자 늦게 감지된다는 점이 헷갈리기 쉬운 포인트)

**EOF란**
- 파일의 끝을 표현하기 위해 정의된 상수(-1)
- EOF도 파일의 내용으로 간주되므로 주의 필요(파일에서 읽을 수 있는 마지막 신호로 취급됨)

**파일 닫기 — `fclose()`**
- 함수 원형: `int fclose(FILE *fp);`
- 열린 파일과 FILE 포인터의 연결을 해제
- 성공 시 0 반환, 실패 시 EOF 반환

## 복습 포인트

- `feof()`는 EOF를 만나는 순간이 아니라, EOF를 읽으려고 **시도한 다음**에야 0이 아닌 값을 반환함 — 타이밍을 헷갈리면 마지막 줄을 두 번 읽거나 빠뜨리는 버그로 이어지기 쉬움
- `fopen()`의 반환값(NULL 여부)은 무조건 확인하고 시작해야 함 — 파일이 없거나 경로가 틀려도 프로그램이 바로 죽지 않고 계속 진행되다가 예상 못한 곳에서 오류가 남
- `w` 모드는 같은 이름의 파일이 있으면 기존 내용을 통째로 삭제하고 새로 만든다는 점 — `a`(추가)와 헷갈리면 기존 데이터가 날아갈 수 있음
